# Spec Delta

## Purpose

Define how the tags and lyrics text is converted into the same ids that heartlib produces: text reading, lowercasing, tag wrapping, tokenization with the checkpoint's tokenizer and adding BOS and EOS, so that the model prompt is identical to Python's for any input.

## ADDED Requirements

### Requirement: Tokenization identical to HuggingFace's
The system SHALL tokenize a text with the checkpoint's `tokenizer.json` giving exactly the same ids as the HuggingFace `tokenizers` library, including BOS at the start and without adding EOS.

#### Scenario: Reference cases
- **WHEN** each of the cases in `tokenizer_cases.json` is tokenized (tags, lyrics, ASCII, Spanish with ñ, accents, Chinese, Japanese, Korean, emoji, newlines, mixed text)
- **THEN** the ids are exactly those of the fixture, starting with BOS 128000 and without EOS

#### Scenario: Edge cases
- **WHEN** the empty string, text with multiple spaces and newlines, numbers, apostrophes, characters outside the BMP or a long text is tokenized
- **THEN** the ids are exactly those of the new cases fixture; the empty string gives only BOS

#### Scenario: Text that looks like a special token
- **WHEN** the text literally contains `<|end_of_text|>` or `<|begin_of_text|>`
- **THEN** it is tokenized as HuggingFace does (as the corresponding special token), with the ids of the fixture

### Requirement: Lowercasing as in Python
The system SHALL lowercase the tags and lyrics text with the same semantics as Python's `str.lower()`, including `İ` and the final sigma rule.

#### Scenario: Final sigma
- **WHEN** `ΑΣ`, `ΟΔΥΣΣΕΥΣ` or `ΣΑΣ ΑΣ.` is lowercased
- **THEN** `ας`, `οδυσσευς` and `σας ας.` are obtained, that is, the sigma at the end of a word is `ς` and in all other positions `σ`

#### Scenario: Dotted I
- **WHEN** `İstanbul` is lowercased
- **THEN** `i̇stanbul` is obtained, with the `i` followed by U+0307

#### Scenario: Remaining fixture cases
- **WHEN** each text of the new cases fixture is lowercased
- **THEN** the result is identical to the one Python stored, character by character

### Requirement: Text preparation as in heartlib
The system SHALL read the tags and lyrics files with universal newlines and without discarding a BOM, and SHALL check the `<tag>` and `</tag>` wrapping with ordinal comparisons, so that the same file gives the same ids on any operating system and culture.

#### Scenario: File with CRLF
- **WHEN** a file whose content uses `\r\n` is read
- **THEN** the resulting text uses only `\n`, and the ids match those of the fixture generated by reading that file with Python

#### Scenario: File with BOM
- **WHEN** a UTF-8 file that starts with a BOM is read
- **THEN** the BOM is kept as the character U+FEFF, and the ids match those of the fixture generated by reading that file with Python

#### Scenario: Tag wrapping
- **WHEN** the tags already start with `<tag>` or already end with `</tag>`
- **THEN** the tag is not duplicated, and the check does not depend on the system culture

### Requirement: Prompt identical to Python's
The system SHALL build, with the real tokenizer and the reference inputs, a prompt identical to the one the golden run used.

#### Scenario: Reference prompt
- **WHEN** the prompt is prepared with `tags.txt` and `lyrics.txt` of the reference inputs using the checkpoint's tokenizer
- **THEN** the tokens, the mask, the positions and the MuQ index are identical to those of `reference.safetensors` (227 positions)

#### Scenario: More pairs of tags and lyrics
- **WHEN** the prompt is prepared with the tags and lyrics pairs of the new cases fixture
- **THEN** the tags and lyrics ids, with their BOS and EOS, are exactly those calculated by heartlib

### Requirement: Command-line use
The `generate` command SHALL use the checkpoint's tokenizer by default, and SHALL be able to use the golden run's precomputed ids if asked with `--ids`.

#### Scenario: Without `--ids`
- **WHEN** `generate` is run with `--ckpt`, `--tags` and `--lyrics` and without `--ids`
- **THEN** the prompt is built by tokenizing the text with `<ckpt>/tokenizer.json`

#### Scenario: With `--ids`
- **WHEN** `generate` is run with `--ids prompt_ids.json`
- **THEN** the prompt is built with the precomputed ids, as until now

### Requirement: Native dependency per platform
The system SHALL resolve the tokenizer's native library according to the operating system and architecture, so that the app and the tests work on Linux, Windows and macOS.

#### Scenario: Per-platform restore
- **WHEN** packages are restored for linux-x64, linux-arm64, win-x64, win-arm64, osx-x64 and osx-arm64
- **THEN** each one resolves its runtime package and it contains the tokenizer's native library
