# model-parity Specification

## Purpose

Define that the C# forward of HeartMuLa (torchtune RoPE, backbone with KV cache and codebook decoder) reproduces the tensors of the Python golden run within fixed tolerances, and that this check runs as automated tests and not by hand.

## Requirements

### Requirement: RoPE equivalent to torchtune's
The system SHALL apply torchtune's RoPE with Llama 3 scaling (rotation over adjacent pairs, `scale_factor` 32) and SHALL give the same result on successive calls with the same input.

#### Scenario: F32 at low and far positions
- **WHEN** RoPE is applied in F32 to the fixture's input at positions 0..15 and at positions 4000..4015
- **THEN** the output differs from torchtune's by no more than 1e-4 in absolute value

#### Scenario: bf16
- **WHEN** RoPE is applied in bf16 to the fixture's bf16 input
- **THEN** each value differs from torchtune's by no more than 1 bf16 ulp

#### Scenario: Repeated calls
- **WHEN** RoPE is applied several times in a row with the same input and positions
- **THEN** all the outputs are identical to the first

### Requirement: Backbone equivalent on the first frame
For the reference prompt with CFG (batch 2), the system SHALL produce the final hidden state and the codebook 0 logits equivalent to Python's.

#### Scenario: Reference prompt in bf16
- **WHEN** the backbone is evaluated on the fixture's prompt with the HeartMuLa-oss-3B checkpoint in bf16
- **THEN** `last_h` and `c0_logits` have the fixture's shape, `cos_sim` ≥ 0.999 and `max_abs` on the logits ≤ 0.5

### Requirement: Backbone equivalent throughout generation
The system SHALL keep the equivalence with Python during the 126 frames of the golden run when the tokens generated by Python are fed back in (teacher forcing), with the KV cache accumulating as in real generation.

#### Scenario: Per-frame logits with teacher forcing
- **WHEN** the backbone is evaluated frame by frame feeding Python's frames back in, for the conditional and unconditional rows separately and before applying CFG
- **THEN** in each of the 126 calls `last_h` and the codebook 0 logits have `cos_sim` ≥ 0.999 and `max_abs` on the logits ≤ 0.5 with respect to the fixture

#### Scenario: No drift over time
- **WHEN** the last 26 calls are compared with the first 26
- **THEN** the worst `cos_sim` of the last ones is not below 0.999 and the `max_abs` tolerance is the same

### Requirement: Decoder equivalent on codebooks 1 to 7
The system SHALL produce the logits of codebooks 1 to 7 equivalent to Python's when the decoder receives the backbone's hidden state and Python's tokens of the previous codebooks.

#### Scenario: Decoder logits with forced tokens
- **WHEN** the decoder is evaluated in bf16 with Python's `last_h` and tokens for the decoder fixture's frames, for the conditional and unconditional rows
- **THEN** the logits of each codebook 1..7 have the fixture's shape, `cos_sim` ≥ 0.999 and `max_abs` ≤ 0.5

### Requirement: Parity runnable as tests
The parity check SHALL run with `dotnet test`, be skipped explicitly when there is no checkpoint, be able to run on CPU or CUDA, and fail without relaxing tolerances when any case does not comply.

#### Scenario: No checkpoint
- **WHEN** `HEARTMULA_CKPT` does not point to an existing directory
- **THEN** the tests that need it are skipped with an explicit reason and the rest of the suite passes

#### Scenario: Chosen device
- **WHEN** `HEARTMULA_DEVICE` is `cuda`
- **THEN** the same parity tests run on the GPU with the same tolerances
